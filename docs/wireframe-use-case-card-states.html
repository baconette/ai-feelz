Wireframe: use case rating card — 3 states

Feature 1, AI Use Case Rating Module — reflects PRD v0.4 (optional descriptions, request-explanation action, conditional negative-rating free-text field). Base rating input shown here is the 5-step snapping slider; the 4 mechanic variants from Round 1 are interchangeable with this card chrome.

StateWhat changesBehavior notes
A — has description Standard layout: description text, rating input, low-emphasis "Request an explanation" link The request-explanation affordance is present on every card, not just missing-description ones, per PRD acceptance criteria ("whether or not it currently has one"). Styled as underlined text, not a button, so it doesn't compete with the rating action for attention.
B — no description yet A dashed-border placeholder replaces the description block; explicitly says "rate based on the name above" Card is fully rateable in this state — this is the PRD's explicit requirement, not a soft degradation. The request-explanation link gets slightly more visual weight here (accent color) since it's the only path to more context, but still isn't a blocking modal or required step.
C — negative rating selected An inline free-text box appears below the rating input, with a "Skip" action alongside advance Triggers only on negative-pole selection. "Skip" and leaving it blank are functionally identical — no validation forces engagement. The request-explanation link stays available even in this state.

Cross-cutting annotations: State C's free-text field should animate in (not jump-cut), since it appears after an action the visitor already completed. The request-explanation link needs real button/role="button" semantics despite link-like styling, since it triggers an action (queues a flag) rather than navigating. Description presence/absence and the negative-pole threshold are both data-driven per use case, from the Notion-sourced dataset — not hardcoded per domain.
